# Target capability survey

This historical survey is cited by the capability registry. Source-level observations and retained smoke artifacts have different evidentiary limits: the Codex and OpenCode receipts originally cited below are unavailable, so their old delivery claims remain unverified. It does not claim an installed model-visible smoke for Cursor or Amp. The current [capability contract](../../../../config/target-capabilities.json) identifies the evidence retained for each registry record.

## Cursor

Cursor IDE 3.11.19 and cursor-agent 2026.05.09-0afadcc expose the native new-composer `sessionStart` hook surface. The installed IDE bundle adds `hook_event_name`, `cursor_version`, `workspace_roots`, `is_background_agent`, and `composer_mode` to the command-hook input and consumes `additional_context` from a valid response. `is_background_agent: true` is the only native background scope used by this adapter; `subagentStart` is a separate lifecycle with no journal context wiring. The retained candidate claim is limited to new-composer sessionStart; resume, compact, and cloud are separately classified as unsupported because no native context trigger is retained for these exact versions. Primary documentation: [Cursor hooks](https://docs.cursor.com/context/hooks) and the installed Cursor IDE bundle (`Cursor.app/Contents/Resources/app/out/vs/workbench/workbench.desktop.main.js`).

## Codex

Codex CLI 0.144.1 retains `SessionStart` hook schemas with `additionalContext` and `systemMessage` fields. This survey historically recorded a successful isolated `darwin-arm64` startup smoke: it enabled hooks in a disposable `CODEX_HOME`, captured the candidate hook output, and observed the model return its random marker. The cited `codex-0.144.1-isolated-startup-smoke.json` receipt is absent from this checkout, and no committed version of that exact path was found in the available Git history during the 2026-11-06 audit. The original smoke claim is therefore unverified from retained artifacts; newer-version receipts do not establish it. Global user-home installation, resume, clear, compact, Windows runtime, and completion capture were separately unproven. Primary tagged sources describe the hook schema, rather than proving model-visible delivery: [SessionStart input schema](https://github.com/openai/codex/blob/rust-v0.144.1/codex-rs/hooks/schema/generated/session-start.command.input.schema.json), [SessionStart output schema](https://github.com/openai/codex/blob/rust-v0.144.1/codex-rs/hooks/schema/generated/session-start.command.output.schema.json), and [Codex hooks documentation](https://developers.openai.com/codex/hooks/).

## OpenCode

OpenCode CLI 1.17.18 exposes request context through `experimental.chat.system.transform` in `output.system` and a compaction transformation through `experimental.session.compacting` in `output.context`. This survey historically recorded an isolated-XDG request smoke that loaded the candidate plugin and observed the model return its random marker, with successful exit, empty stderr, no supplied auth, cleanup, and candidate artifact hashes. The cited `opencode-1.17.18-isolated-request-smoke.json` receipt is absent from this checkout, and no committed version of that exact path was found in the available Git history during the 2026-11-06 audit. The original smoke claim is therefore unverified from retained artifacts; newer-version receipts do not establish it. Startup had no distinct native signal; resume and compact remained candidates. Completion remained disabled: bash exit status was source-proven, but operation success and durable identity were unproven. Bypass cases included a missing or disabled plugin, an attached or remote server without it, missing state, and an untested version. [OpenCode plugin documentation](https://opencode.ai/docs/plugins/) describes the integration surface; it does not replace the unavailable smoke receipt.

## Amp

Amp CLI 0.0.1783873056-g278461 exposes `tool.call` and `tool.result`, but there is no proven root identity for automatic context delivery; `agent.start` is retained only as a foreground-turn candidate trigger whose exact reason is that root-only identity cannot be proven. Startup, resume, and compact have no distinct native context signals and are unsupported, so the honest fallback is the managed instruction plus explicit `loaf journal context`. Foreground children are indistinguishable from the root, so subagent/background policies are explicitly disabled. Generic done/error/cancelled signals are source-proven, but durable operation success, identity, and child suppression remain unproven; completion capture is disabled. Candidate plugin discovery is under `XDG_CONFIG_HOME/amp/plugins` or `HOME/.config/amp/plugins`; a missing or disabled plugin, a legacy-only `~/.amp` install, missing Loaf state, and an untested harness version are explicit bypasses. Legacy `~/.amp` retirement belongs to U9. Primary documentation: [Amp manual](https://ampcode.com/manual).
